AERIVA · plan for discussion

Connecting the simulator to the live engine

A small FastAPI server runs on your laptop next to aeriva_core. It loads the DCT files once, fits the model, and answers each screen's questions over http://localhost:8000. The simulator page is served by that same server, so every number comes straight from the engine instead of from a copied export file.

Nothing here is built yet. This page shows the architecture, the endpoints mapped to your engine's real functions, a wireframe of each screen with the endpoint behind every block, and the build steps.

01Architecture

Three parts, all on your laptop. The browser only talks to the API; only the API touches the engine; only the engine reads the Excel files. The heavy work (reading 15 MB of flights, fitting, back-testing) happens once at start-up and is cached, so each click is answered in milliseconds.

Browser (simulator HTML)New: API serverExisting engineDCT data

Today: snapshot static

  • Engine runs once; results copied into aeriva_sim_data.json inside the page.
  • The page repeats the formulas in JavaScript.
  • About 10 figures are typed in by hand.
  • New data means re-export and rebuild.
  • Works anywhere, including the claude.ai link.

Planned: live engine local API

  • The engine answers every request; the page only draws.
  • One source of truth: Python, not a JavaScript copy.
  • No typed figures: all come from /api/meta and /api/evidence.
  • New data: drop files, click Refit.
  • Runs at localhost:8000 while the server is on.

The published claude.ai link cannot call your laptop (its security rules block requests to other addresses), so it stays the offline snapshot. The live version opens at http://localhost:8000. When it is hosted later, the same page points at the hosted address instead.

05Feeding in new data

  1. Copy the new DCT Excel files into data/, same names and columns as today.
  2. Open Evidence Lab → Refit with new data, or call POST /api/admin/refit.
  3. The server runs the engine steps in order: load and check (integrity_report), build the panel, fit L2, back-test, nowcast, grades. Progress shows in the page.
  4. When done, the new state replaces the old one in memory and in cache/ with a new data version. The old version is kept, so a bad file can be rolled back.
  5. Every screen refreshes; the header shows the new version and date; new months appear in the month lists by themselves.
If a new file fails the integrity checks (missing columns, duplicates, load factors above 120%), the refit stops before anything is replaced, and the page lists what failed.

06What gets built

New folder next to aeriva_core

aeriva_work/ ├─ data/ # DCT files (existing) ├─ aeriva_core/ # engine (unchanged) └─ aeriva_api/ # new ├─ main.py # app, CORS, serves the page ├─ state.py # load, fit, cache, version ├─ schemas.py # request/response shapes ├─ routes/ # one file per screen ├─ static/ # simulator HTML + api.js ├─ cache/ # saved engine state └─ tests/ # API returns brief numbers

Start with one command: uvicorn aeriva_api.main:app --reload, then open http://localhost:8000.

Build order

  1. State loader + cache. Load files, fit, back-test once; save to cache/.
  2. /api/meta and /api/radar. Radar works live end to end.
  3. /api/scenario + series. Studio and Decision Card.
  4. /api/evidence + replay. Removes every typed-in figure.
  5. Offline fallback to today's snapshot, and the status light.
  6. Tests that the API reproduces the brief: +7,087 for Kuwait Aug 2024 +20%; WAPE 18.5% and total 5.7%.
  7. Refit endpoint and admin panel.

07Decisions to make before building

Server-side PDF or keep the browser export? A server PDF can carry the data version and higher quality; the browser export already works.
Where the scenario logic lives. Plan: all in Python (scenario.py already has seats %, flights, route cut, new seats and stopover; it gains market mix, the sensitivity runs and the driver split). The page then holds no model maths.
Hosting later. The same server can move to a host (Render, Railway or a university server) and add the password there. Nothing in the page changes except the address.
